Without Hiero React (~20 lines)

const [balance, setBalance] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError]     = useState(null);

useEffect(() => {
  fetch(`https://testnet.mirrornode
    .hedera.com/api/v1/accounts/${id}`)

        data.balance.balance / 100_000_000

b. Feasibility & Business Model

Why this must be Web3.

Web3-native by nature

The data we surface — HBAR balances, token holdings, HCS messages, smart contract logs — exists only on the Hedera distributed ledger. There is no Web2 equivalent. The Mirror Node API is the data source, and React hooks are the developer bridge.

Domain understanding

  • Mirror Node REST API structure and pagination
  • Tinybar-to-HBAR conversion (10^8)
  • Base64 encoding for HCS messages and NFT metadata
  • Hedera entity ID format (shard.realm.num)
  • Network-specific endpoint routing

c. Future Roadmap

Key learnings & what's next.

Key Learnings

Mirror Node is underutilized

The REST API exposes rich data, but few tools make it accessible. Wrapping it in familiar React patterns dramatically lowers friction.

Read-first is the right entry point

Starting read-only avoids key management complexity and lets developers explore Hedera data safely before committing to write operations.

Zero dependencies = maximum trust

No external runtime dependencies made the library easy to audit, fast to install, and safe from supply-chain risks.
